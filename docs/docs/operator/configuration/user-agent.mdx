# User-Agent

Every request to the Kubernetes API server carries a `User-Agent` header. The API server records it in its
audit logs, and for a write without an explicit `fieldManager` it derives the field manager from the part of
the user agent before the first `/`. The official C# client sends `kubernetes-csharp/<version>`, so without an
own user agent every client built on it looks the same to the API server.

The operator replaces that default with the operator name, the version of the operator, KubeOps and the C#
client:

```text
my-operator/1.2.0 kubeops/15.0.0 kubernetes-csharp/21.0.8
```

- **`my-operator`** is the operator name set with `WithName`. Characters that are not allowed in an HTTP
  product token, e.g. spaces or `/`, are replaced by `-`.
- **`1.2.0`** is the informational version of the entry assembly, i.e. of your operator. It is left out
  when there is no entry assembly.
- **`kubeops/…`** and **`kubernetes-csharp/…`** are the versions of KubeOps and of the C# client.

In audit logs, requests of the operator can be told apart from those of other clients. Field managers are not
affected: the operator sends every write with its [field manager](./field-manager), so the API server does not
fall back to the user agent. The user agent is independent of `WithFieldManager` and always starts with the
operator name.

## Setting an Own User-Agent

The operator only replaces the default user agent of the C# client. Register a `KubernetesClientConfiguration`
with an own `UserAgent` to keep it:

```csharp
var config = KubernetesClientConfiguration.BuildDefaultConfig();
config.UserAgent = "my-operator/1.2.0 (team-a)";

builder.Services.AddSingleton(config);
builder.Services.AddKubernetesOperator(settings => settings.WithName("my-operator"));
```

An `IKubernetes` that you register yourself uses the user agent of its configuration as it is. Use
`KubernetesUserAgent` to give it the user agent of the operator:

```csharp
builder.Services.AddSingleton<IKubernetes>(services =>
{
    var config = services.GetRequiredService<KubernetesClientConfiguration>();
    var settings = services.GetRequiredService<OperatorSettings>();

    KubernetesUserAgent.SetIfNotConfigured(
        config,
        KubernetesUserAgent.CreateFromAssembly(settings.Name, Assembly.GetEntryAssembly()));

    return new Kubernetes(config, new FieldManagerHandler(settings.FieldManager));
});
```

The user agent has to be set before the `Kubernetes` instance is created; the client reads it only once.

## Outside the Operator

`KubernetesUserAgent` is part of `KubeOps.KubernetesClient`, so CLIs, migration jobs and other tools can use it
as well:

```csharp
var config = KubernetesClientConfiguration.BuildDefaultConfig();
KubernetesUserAgent.SetIfNotConfigured(config, KubernetesUserAgent.Create("my-migration", "2.0.0"));

using var client = new KubernetesClient(config, "my-migration");
```

The KubeOps CLI identifies itself as `kubeops-cli/<version>`.
